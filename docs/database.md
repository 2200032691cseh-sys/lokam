# PostgreSQL logical schema

Use internal bigint keys, opaque public IDs for private objects, UTC technical timestamps, FK indexes and explicit deletion actions. Preserve original Unicode. Optional narrative dates carry precision. Key relations and migration contracts follow.

| Area | Tables and constraints |
|---|---|
| Identity | Custom User precedes initial migrations. Unique normalized username/email. Profile 1:1 with settings, optional avatar/introduction and visibility. ProfilePage unique owner/page key and owner/position; enabled and visibility. EmailVerification token digest, expiry and consumption; Django sessions plus session generation. |
| Catalogue | CatalogueItem with kind, subtype, title, eligibility and merge redirect. CatalogueAlias unique item/language/normalized alias. ExternalIdentifier unique provider/namespace/value. CatalogueSource captures revision, validated fields, terms and retrieved date. CatalogueImage records source, credit, licence and delivery policy. |
| Detail | One-to-one kind records Book, BookEdition (parent work), Movie, TVShow, TVSeason (show/number unique), TVEpisode (season/number unique), MusicArtist, MusicAlbum, MusicRelease, MusicRecording, MusicalWork, HistoricalEntity, Culture, Place (coordinate checks), Cuisine, Dish, Language, MythologicalEntity, Concept, Activity and LearningResource. Documentary is film/TV subtype; restaurant/museum are Place subtypes; lecture/video/podcast are LearningResource subtypes. Person and ItemPersonRole capture ordered credits. Genre, Theme, Tag and ItemTag use distinct vocabularies and unique joins. |
| Graph | CatalogueRelationship unique subject/predicate/object with allowed endpoint types, directional predicate and verification state. RelationshipEvidence has source/assertion/revision; indexes on both endpoints plus predicate. ProviderSuggestion is expiring, source-attributed and independent. UserItemRelationship belongs to owner; computed similarity is derived. |
| Library | UserItem unique owner/item with checked domain state, optional rating, favourite flag and visibility. UserNote, UserQuote and UserItemTag have scoped references; typed annotations cover editions, ownership, passages, characters, scenes, performances, episodes, musical associations, words and phrases. Owner-discriminated custom entities stay out of global indexes and graph enrichment. |
| Publishing | Collection + CollectionItem with ordered entries and XOR canonical item/personal save target. Bookmark unique owner/public collection, checked at read. BucketListItem uses canonical/custom target, visibility and optional fulfilled state. Memory, Album, AlbumMedia, MemoryMedia, TimelineChapter and TimelineItem use typed relations, order and scoped visibility. Home feature joins target authorised rows via explicit FKs. |
| Discovery | ExplicitPreference unique user/subject/type. DiscoveryConfiguration stores reset generation. RecommendationFeedback unique user/candidate/scope. CatalogueEmbedding unique canonical item/model revision/content hash. Optional expiring snapshots store evidence IDs with read-time authorization. |
| Social | Follow unique directed pair with pending/accepted state, Block unique directed pair, self-checks and reverse indexes. Notification recipient/dedup key. Report with scoped assignment, target and evidence. Append-only ModerationAction and minimized AuditEvent. |
| Operations | MediaAsset owner, opaque key, status, hash, quota bytes, variants. BackgroundJob kind/state, unique dedup key, attempts, available time and lease/token. ImportJob/ExportJob owner, version and temporary artifact. ProviderSyncState quotas/cache/circuit state. Erasure marker for restore replay. |

Use owner-scoped writes and composite owner constraints where IDs are repeated. Reorder transactionally with deferrable positions. Merge exact IDs or administrator-approved matches under ordered locks. Dry-run collisions, redirect loser, rewire graph and dependent rows, retain annotations and audit. Let erasure cascade personal rows and enqueue media cleanup; protect shared canonical rows. Use JSONB for versioned supplementary data and manifests only. Use separate migration credentials, expand/backfill/validate/contract migrations and PostgreSQL integration tests.
